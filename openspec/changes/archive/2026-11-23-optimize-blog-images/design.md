# Design

## Context

See `proposal.md` for motivation. The site is generated by blogatto from
`blog/<slug>/index*.djot`; post-adjacent files are copied into `dist/` and
served by base name. Templates render `post.featured_image` as the masthead
background on post pages, as an OpenGraph-style card on the home page, and as
the card image on the blog index. CSS already applies `background-size: cover`
and `object-fit: cover` where a display crop is needed, so no Gleam template or
route changes are required: this change standardizes the underlying files.

The current content has 101 distinct `featured_image` values across 404
frontmatter lines: 97 local rasters, one local SVG, three remote URLs, and the
shared `/img/Ninjas.png`. There are 17 distinct remote image URLs used by
posts, including those three covers, across seven post slugs. `static/` holds
about 2,347 images that must remain byte-for-byte unchanged.

## Goals / Non-Goals

**Goals:**

- Make every image reference in a post resolve to a file under `blog/<slug>/`.
- Optimize each blog image once per content hash, with a committed root
  manifest that survives fresh clones and detects manual edits.
- Give every `featured_image` a local 1280x720 center-cropped derivative while
  leaving the optimized original available for inline figures.
- Provide one standard command that installs the Python tool's dependencies
  and runs it, and wire deployment to run it before building.

**Non-Goals:**

- No changes to `static/` or to files copied from it into `dist/`.
- No Gleam, Lustre, CSS, routing, CI, or blogatto configuration changes.
- No optimization of SVG source files; the one SVG cover gets a raster
  derivative only.
- No localization of video embeds, YouTube/archive.org iframes, external card
  links, or remote images that are not referenced by posts.
- No change to the current CSS crop behavior.

## Decisions

### A Python tool under `tools/optimize/`

Use Python 3.14+ and Pillow in `tools/optimize/`, with a nested
`tools/optimize/Taskfile.yml` exposing dependency installation, a default run,
and tests. A `pyproject.toml` pins Pillow and declares
`requires-python = ">=3.14"`; `uv sync` installs into a local `.venv` that is
git-ignored.

Alternatives considered:

- **Erlang/OTP alone** — rejected. OTP has no PNG/JPEG codec; `erl_img` is
  JPEG read-only, Hex `png` is encoder-only, `eimp` needs native C libraries,
  and `wxImage` needs a wx runtime. Wrapping a Python worker would keep the
  Python dependency and add a layer.
- **Go** — rejected. The standard library covers PNG/JPEG/GIF but not WebP or
  AVIF, which are present in the posts; extra modules/native libraries would
  be heavier than Pillow.
- **Mogrify/ImageMagick** — explicitly excluded by the requirement.

Pillow 12.3.0 is locally available, supports every raster format in the
content, and declares `Requires-Python >=3.10`, so the 3.14 floor is safe.

### Source-level localization, not generated-HTML rewriting

Download the 17 remote images into the post directories and rewrite the 28
affected djot files. This makes the repository itself self-contained, uses
blogatto's existing post-extra copying for `dist/`, and avoids network access
during site builds. A build-time fetcher that rewrote generated HTML would
leave the source dependent on external hosts and add a fragile transformation
step.

The local filename is the URL's basename with query strings removed; a short
SHA-256 suffix disambiguates collisions within a post. Downloads use a browser
User-Agent, verify the response through Pillow, and fail loudly rather than
leaving a broken local reference. The manifest records URL-to-path mappings so
a later run reuses the local file without another request.

### Derivative covers, not in-place cropping

For every resolved `featured_image`, write `<stem>-1280x720.<ext>` beside the
optimized original using `ImageOps.fit` with LANCZOS resampling and
`centering=(0.5, 0.5)`. `ImageOps.fit` scales first and crops from the center,
so images that are too small are upscaled and every derivative fills the frame
without letterboxing. Frontmatter lines are rewritten to point at the
derivative; inline `![...](...)` references keep pointing at the original.

This avoids two problems with in-place cropping: 372 of 392 post variants show
the cover file again inline, and `/img/Ninjas.png` is also the site logo and
OG fallback. For the welcome post, `static/img/Ninjas.png` is copied to
`blog/bienvenidos-a-ninjas-cl/Ninjas.png`, then optimized and given a
derivative there; the static original is never modified.

The single SVG cover is left unchanged as an original and gets a rasterized
`cover-1280x720.png` derivative. Pillow cannot rasterize SVG itself, so the
nested Python project also pins `resvg-py`, a self-contained wheel that renders
SVG to PNG bytes. This keeps the pipeline free of ImageMagick/Mogrify and adds
no native dependency to the Gleam project.

### Conservative per-format optimization

| Format | Settings |
| --- | --- |
| PNG | `optimize=True`, `compress_level=9`, lossless |
| JPEG | `quality=85`, `optimize=True`, `progressive=True`, 4:2:0 subsampling |
| WebP | `quality=85`, `method=6` |
| AVIF | `quality=60`, `speed=6` |
| GIF | `optimize=True`, preserving frames, durations, and loop count |

These are web-quality defaults rather than the old `compress.exs` aggressive
posterize/quality-55 settings. Cropping does most of the size reduction (for
example, an 11 MiB PNG becomes about 1 MiB as a 1280x720 PNG), so degrading
inline artwork is unnecessary. RGBA is preserved for PNG/WebP/AVIF; JPEG and
other RGB-only targets are converted from RGBA before saving.

### Root content-hash manifest

`optimize-manifest.json` at the repository root, beside `manifest.toml`, is
committed and contains:

- `images`: relative path to SHA-256 of the file's final bytes.
- `downloads`: remote URL to the chosen local relative path.
- `covers`: original image path to its derivative path.

A run computes SHA-256 before decoding. If the path's hash is recorded, the
file is skipped untouched. Otherwise it is optimized, written atomically, and
the new hash is recorded. Derivatives and downloaded originals use the same
rule. If a user edits a file, its hash no longer matches and it is processed
again. The manifest is therefore format-agnostic, works for GIF, and survives
fresh clones, unlike an in-file marker.

The tool excludes `*-1280x720.*` derivatives from the original-image scan so
they are never cropped recursively. It also never walks `static/`.

### Task wiring

`tools/optimize/Taskfile.yml` owns dependency installation and the default
run. The root `Taskfile.yml` gains an `optimize` task that delegates to
`task -d tools/optimize`. `upload` calls `optimize` and then `build` as ordered
commands rather than parallel dependencies, preserving the current build and
SFTP diff logic. Plain `task build` stays a build only; the content is already
optimized in the repository after the one-time migration.

## Risks / Trade-offs

- **[Risk] A center crop can remove meaningful content from logos, diagrams, or tall screenshots** → Mitigation: only `featured_image` targets are cropped; originals remain for inline use, and the derivative is visually reviewable in `git diff`.
- **[Risk] Remote hosts change or remove a source image** → Mitigation: the 17 files are committed under `blog/`; after migration no build or page view depends on those hosts.
- **[Risk] Re-encoding a recorded file could still churn bytes if a codec is non-deterministic** → Mitigation: hash checks skip recorded files before decode; manifest updates are atomic and only written after successful writes.
- **[Risk] One-time upload grows because every image changes** → Mitigation: expected and bounded; the manifest makes subsequent deploys stable.
- **[Risk] AVIF/WebP settings vary with Pillow builds** → Mitigation: pin Pillow in `pyproject.toml`, verify format support in tests, and skip unsupported formats with an explicit error rather than silently producing broken files.
- **[Risk] SVG rasterization depends on a Python wheel with native bits** → Mitigation: pin `resvg-py`, keep the original SVG unchanged, and fail with an explicit message if rendering fails; only one post is affected.
- **[Risk] The committed manifest drifts from content** → Mitigation: `tools/optimize --check` verifies that every recorded hash matches current bytes and reports pending work without writing.

## Migration Plan

1. Add the tool, manifest schema, unit tests, root task, and documentation.
2. Run the tool once locally: it downloads 17 images, optimizes blog images,
   writes derivatives, and rewrites 28 djot files plus 404 `featured_image`
   lines.
3. Review the diff for image changes and frontmatter rewrites; confirm
   `static/` is unchanged and generated pages contain no remote post-image
   URLs.
4. Run the Python tests, `gleam format --check src test`, `gleam test`, and a
   full `task build`.
5. Deploy normally with `task upload`; expect a one-time bulk image upload.
6. Rollback by reverting the content and manifest commit; no server-side state
   or generated-HTML rewrite needs to be undone.
