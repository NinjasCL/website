# Design

## Context

The repository is a Gleam 1.18 project (`src/`, `test/`) intended to generate the Ninjas.cl static site with blogatto (>= 8.0.0, < 9.0.0; Lustre/mist-based) on Erlang/OTP. Today `src/website.gleam` is a placeholder and no content/output directories exist. See `proposal.md` (Why, What Changes, out-of-scope) for motivation and scope; this design covers how the core engine is bootstrapped.

## Goals / Non-Goals

**Goals:**
- Provide a working core blogatto build pipeline from `gleam run` that generates Ninjas.cl site pages.
- Establish clear, conventional locations for posts, templates/views, static assets, and generated output.
- Keep implementation minimal and aligned with blogatto 8 APIs so feeds/sitemap/robots/content migration can be added later.

**Non-Goals:**
- RSS/Atom, sitemap, robots.txt, multilingual post variants, theme/CSS parity, content migration, or extra non-blog routes.
- Changing the blogatto dependency range or Gleam/OTP/CI versions.
- Introducing a deployment pipeline or runtime dev server workflow in committed behavior.

## Decisions

### 1. Build orchestration in `src/website.gleam`
- **Decision:** Implement `main` to construct a blogatto config and call `blogatto.build(config)`, reporting success/failure (e.g. `blogatto/error.describe_error`) and exiting appropriately on failure.
- **Rationale:** Matches blogatto’s single-entry build model and keeps `gleam run` as the site-generation command expected by the project.
- **Alternatives:** Split config/build into modules immediately — deferred until complexity warrants it; initial implementation may extract pure helpers only if it improves clarity/testability without adding scope.

### 2. Site configuration and identity
- **Decision:** Use `blogatto/config.config.new("https://ninjas.cl/")` as the base URL and configure Ninjas.cl identity in rendered pages/templates: title `Ninjas.cl`, description `Ninja Software Is an Experimental Software Developer Group from Chile 🇨🇱. Participates in various technological projects like videogames, software and other related activities.

Ninjas.cl was started in 2015 (11 years of coding ❤️!) by Camilo Castro.`, and default language context Spanish (Chile, `es-CL`, e.g. via document `lang` attributes in templates/views).
- **Rationale:** Satisfies clarified site identity; language is applied at template/document level in core generation (no multilingual post variants in scope).
- **Alternatives:** Hardcode strings only in one view — rejected in favor of consistent config/constants used across home/post templates.

### 3. Content files and post loading
- **Decision:** Store posts under `blog/` (repo root) and configure with `blogatto/config/post`: `post.default() |> post.path("./blog") |> post.route_prefix("blog")` (assumption: conventional blogatto layout; final path/prefix recorded in code/tasks). Posts are Markdown with blogatto frontmatter (minimum `title`, `date`, `description`; `slug` optional). Include at least one minimal sample post to validate generation.
- **Rationale:** Aligns with blogatto examples/docs and keeps content separate from `src/`.
- **Alternatives:** Use `content/` or another directory — acceptable if chosen consistently; `blog/` is the default assumption for this bootstrap. Multilingual `index-{lang}.md` variants are out of scope.

### 4. Routing and templates
- **Decision:** 
  - **Home:** `config.route("/", home_view)` renders a Lustre page listing posts (sorted newest-first) with links to post routes.
  - **Posts:** per-post pages generated by blogatto from the post config; rendered via `post.template(post_template)` producing a full Lustre HTML document that includes post metadata/title/description and `post.contents`. Route form follows `route_prefix` convention (e.g. `/blog/<slug>/`) unless adjusted consistently during implementation.
- **Rationale:** Covers core “blog engine” behavior (index + article pages) with standard blogatto/Lustre APIs.
- **Alternatives:** Custom `post.route_builder` or additional routes — out of scope for core generation; can be introduced in a follow-up change.

### 5. Static assets and output
- **Decision:** Use `static/` for source static assets (`config.static_dir("./static")`) and `dist/` for generated output (`config.output_dir("./dist")`). Ensure generated output is not committed (update `.gitignore` to include `dist/` if needed).
- **Rationale:** Separates source assets from build artifacts and matches common blogatto usage.
- **Alternatives:** Output to `build/` — avoided to prevent confusion with Gleam’s `build/` compiler output (already git-ignored).

### 6. Dependencies
- **Decision:** Do not add new packages. The implementation imports Lustre directly for views and `gleam_time` for displaying post dates, so both are declared as direct dependencies at their already-locked versions (`lustre >= 5.7.1 and < 6.0.0`, `gleam_time >= 1.11.0 and < 2.0.0`); `blogatto` remains `>= 8.0.0 and < 9.0.0`.
- **Rationale:** blogatto provides configuration, content parsing, and build orchestration, but views use Lustre elements and date formatting uses `gleam_time`. Declaring them directly avoids transitive-import warnings (and future compile errors) without introducing new packages or version changes.

## Risks / Trade-offs

- **[Risk] Assumed content/routing conventions differ from desired Ninjas.cl structure** → Mitigation: record assumptions in proposal/design/tasks, keep paths/prefix centralized in config, and adjust in a follow-up change if needed.
- **[Risk] `blogatto.build` is IO-heavy and hard to unit test directly** → Mitigation: keep view/template helpers pure where practical and verify generation via `gleam run`/output checks and standard CI commands; add focused tests for deterministic helpers if introduced.
- **[Risk] `dist/` accidentally committed** → Mitigation: add/verify `.gitignore` entry and include verification in tasks.
- **[Risk] API differences within blogatto 8.x** → Mitigation: follow locked/resolved 8.0 APIs during implementation and validate with `gleam test`/`gleam format --check src test`.

## Migration Plan

- No migration of existing Ninjas.cl content in this change. Implement core generation alongside sample content, verify locally with `gleam run`, then iterate in future changes (content import, feeds/sitemap/robots, styling).
- Rollback: revert the change commits to restore the placeholder entrypoint and remove added content/output conventions.

## Open Questions

- None that block this core bootstrap; URL/content refinements beyond the stated assumptions can be handled in follow-up changes without altering the core capability contract.
